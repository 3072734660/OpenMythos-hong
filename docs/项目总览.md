# 项目总览

OpenMythos-hong 是一个三档 MoE 模型工程初始化版本，目标是在同一套接口下覆盖调试、本地低显存运行和集群训练。

本仓库不包含个人训练流程产物，不包含生成数据脚本，不包含评测脚本，不包含训练好的 checkpoint。它提供的是模型代码、配置、训练入口、服务入口和中文说明文档。

## 设计目标

1. **三档模型同构使用**：tiny、本地小 MoE、集群 MoE 使用相同配置字段、相同训练入口、相同服务接口。
2. **公开预训练模型优先**：本地小 MoE 和集群 MoE 使用公开 Hugging Face 模型，不把外部模型强行转换为 OpenMythos 自定义权重。
3. **本地可服务**：训练或下载权重后，可以不依赖 Ollama，直接启动 Python HTTP 服务。
4. **低显存友好**：本地 CUDA 档默认面向 3050Ti 4GB，使用 4-bit/8-bit、LoRA/QLoRA、短上下文和 offload。
5. **缓存友好**：服务端支持完全相同请求的 response cache，也支持多轮会话中追加消息时的前缀/KV cache。

## 三档模型

### tiny 调试模型

- 位置：`open_mythos/public_moe/tiny_true_moe.py`
- 配置：`configs/family_tiny_moe_quant.yaml`
- 作用：验证训练代码、服务代码、量化流程、缓存接口。
- 特点：参数量极小，真实包含 router 与 experts。

### 本地 CUDA 小 MoE

- 默认模型：`allenai/OLMoE-1B-7B-0125`
- 配置：`configs/family_small_moe_3050ti_4g.yaml`
- 作用：在 3050Ti 4GB 这类小显存 GPU 上做低显存 LoRA/QLoRA 微调。
- 特点：公开 MoE 权重，默认启用量化加载和低显存配置。

### 集群 MoE

- 默认模型：`Qwen/Qwen1.5-MoE-A2.7B`
- 配置：`configs/family_cluster_moe_smaller_than_oss20b.yaml`
- 作用：多卡或集群环境下训练更大 MoE。
- 特点：比 oss-20b 更小，更适合作为中等规模集群实验入口。

## 不包含的内容

本初始化仓库刻意不包含：

- 用户训练数据。
- 自动数据生成脚本。
- 评测脚本和评测报告。
- 训练出的 checkpoint。
- 大模型权重。
- 本地实验日志。

这样做是为了让仓库保持干净，可公开、可复现、可扩展。
