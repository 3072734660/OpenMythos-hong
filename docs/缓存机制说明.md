# 缓存机制说明

服务端包含两类缓存。

## response cache

完全相同的 prompt/messages 和生成参数再次请求时，直接返回上次结果，不重新推理。

## prefix/KV cache

多轮对话中，第二次请求通常是在第一次上下文后追加新消息。prefix/KV cache 会复用旧上下文的 KV，只计算新增部分，避免每次从头 prefill 全部历史。

返回字段示例：

```json
{
  "cache_hit": false,
  "prefix_cache_hit": true,
  "prefix_cache_tokens": 128,
  "prefill_tokens": 24,
  "generated_tokens": 64
}
```

含义：

- `cache_hit`：是否完全命中 response cache。
- `prefix_cache_hit`：是否复用已有前缀 KV。
- `prefix_cache_tokens`：复用的历史 token 数。
- `prefill_tokens`：本次仍需计算的新输入 token 数。
- `generated_tokens`：本次生成 token 数。

对于 Hugging Face 模型，如果模型不支持标准 `past_key_values` 复用，服务会自动回退到普通 generate，保证正确性优先。
